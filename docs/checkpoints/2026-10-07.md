# Checkpoint, 2026-10-07: Ask on paper

This checkpoint records what is running and verified on the hardware after two days of work on
native agent ink. It also covers how to bring the stack up and what is still open. The design
direction that follows from it is in `docs/design/ask-experience.md`.

dev at this checkpoint: `fd891d9` and the commits of this checkpoint. Tablet release:
`2026.10.07-065136-fd891d9-ce21` (Paper Pro, OS 3.29.0.149, XOVI on, engine rust).

## What a user can do now (verified on the device)

1. **Ask about a lasso or a page.** There are two ways to ask:
   - lasso some ink, then tap the "c" button the extension adds to xochitl's own selection menu,
     after delete;
   - use the "c" dock under redo in the left toolbar: *Ask about this page* or
     *Ask about selection*.
2. **See it think at once.** A doodle appears at the tap, 36 page units (about 4 mm) under the
   selected ink. It is drawn by the tablet without waiting for the network, it stays on the
   paper while the page scrolls or zooms, and it is never saved. When the answer starts, the
   doodle's nib hands off into it.
3. **Read the answer in ink.** About 3–4 s after the tap, the answer starts writing itself in
   under the selection:
   - in a biomechanical hand (`packages/hand`, the Archivist), at about 7 letters/s ("fast");
   - as native reMarkable strokes on the "codrawer: agent" layer, which one undo removes;
   - at a comfortable width, with compact spacing, never over existing ink, and kept on the
     page.
4. **Keep writing meanwhile.** The user's pen is never blocked: the overlay takes no input and
   covers only what it draws. Native commits switch layers in a window of 16–50 ms (mean 19 ms
   over 107 commits), with no strokes misfiled so far. A commit made *while the user's pen is
   down* has not been observed yet, so that case is still open.
5. **Follow a thread.** Asks on the same page carry the page's earlier exchanges as text (memory,
   on by default; local only; per page).
6. **Tune it from the dock.** agentd publishes these rows into the tablet's dock: Memory, Forget
   this page's thread, Model (careful = Sonnet 5.5 / fast = Haiku 4.5), Text size (micro … large),
   Spacing (compact / normal / airy) and Writing speed (calm / fast / very fast).

## How it is wired

```
tablet: xochitl + XOVI codrawer-layer.so ── ink.sock ── bridge (rust) ── router :8577 (session1)
                                                                             │  Wi-Fi / tailnet
PC:                                              codrawer-agentd ───────────┘
                                                   └─ pool of warm `claude -p` processes (stream-json,
                                                      image attached, no tools, empty cwd outside the repo)
```

- **Extension** (`bridge/remarkable/xovi/codrawer-layer/`, literate modules):
  - the ink commit chain;
  - the live overlay (`qml/live.qml`);
  - the dock, the selection "Ask" button, automation, goto, and the probes.
- **Bridge and routers** (`bridge/remarkable/native`, `bridge/remarkable/rust`):
  - relay `dock_action`, `agent_status`, `settings`, `dock_entries` and `goto`;
  - govern agent ink: 30 strokes/s with a burst of 60; y up to 40000 page units.
- **agentd** (`src/codrawer_bridge/agentd/`):
  - placement, rendering and the page model;
  - the warm process pool (`claude_stream.py`) and page threads (`threads.py`);
  - streaming sentence by sentence into the warm hand worker.

### Run agentd

```bash
uv run python -m codrawer_bridge.agentd --ws ws://<tablet-ip>:8577/ws/session1 --token <ROUTER_TOKEN> \
  --ssh root@<tablet-ip> --backend claude-stream --agent-cwd ~/.codrawer-agentd/live \
  --thinking overlay --max-page-y 18
```

It uses the Claude Code subscription login; no API key is needed. Logs and request records go
to `.codrawer/agentd/` (gitignored); settings and page threads stay local.

## Incidents and the rules they left

- **The user's pen was blocked** (2026-10-07 00:00). The first live overlay was a full-page
  Canvas above the page, and xochitl does not let the pen write under another item. Fixed in
  `fe43cd1`. Rule: after every XOVI reload, the first check is that the user's pen writes,
  together with `scripts/dev/pentest.py`. Nothing of ours may take input or cover more than
  it draws.
- **Answers were lost on scrolled pages.** The bridges refused y above 1.5 page heights; fixed in
  `b1331c4`.
- **A late answer reached the wrong ask.** An interrupted Claude turn's result was read by the
  next turn. Now every ask gets its own process, so a tainted session is never reused.
- **A bloated session.** Every image stayed in one long session (turns took 30–70 s). Now each ask
  runs in a fresh, pre-warmed process.

## Open

- **A commit while the user's pen is down:** collect `ink: window … pen down` lines during a long
  answer while the user keeps writing.
- **The doodle's placement** (see the design doc): the tablet proposes the spot and agentd
  confirms it; a move becomes one arc, never two jumps. The extension also has to read the real
  selected-ink bounds; today it reads `textSelectionBounds`, which is 0×0 for ink.
- **A live stroke may block the pen at its own spot while it plays.** Check whether the
  Animation region is the cause.
- **agentd runs in a terminal, not as a service.** It also needs a health row in the dock and a
  nightly on-device regression.
- **The screen grab's colours are still shifted** (open since Probe 1).

### Gestures on answers (strike, circle, "?", tick)

Branch: `feat/answer-gestures`. Only the design is done; no code yet. Nothing was deployed.

**What the investigation established.**

- **Erase natively with `SceneController::eraseWithLine(Line)`.** It is xochitl's own pen-up erase
  (DocumentView QML: `else if (stroke.isEraserTool) controller.eraseWithLine(stroke)`). It takes no
  layer argument, so it acts on the current layer; the sibling ops take one explicitly
  (`deleteSelectedItems(currentLayer)`, `clearLinesInLayer(currentLayer)`). It is undoable.
  `addSelectionRect` + `deleteSelectedItems` were rejected: they change the user's visible
  selection state.
- **An eraser Line is built with `buildLine(tool 6, …)`**, along the stroke's own points, at
  thickness 1. The reach is 5 × thickness + the ink's half width (native-erase.md §1), so the
  stroke goes whole (every point is at distance 0), and nothing more than ~7 px away is cut.
- **Lasso strokes stream from the bridge as brush `pen`.** A lasso around an answer would read as
  a circle. Recognition therefore needs the extension's own report of each user stroke, from
  `strokeCompleted(Line)`: its tool, its page bbox and the current view.
- **`stroke_delete` cannot carry the erase.** The router drops ids that a `page` snapshot covers.
- **packages/marks is not reused.** Its recogniser is few-shot and learned (a "?" would have to be
  taught first), and it is TypeScript. delegate's built-in shape rules (`packages/delegate/src/marks.ts`:
  loop, line, tick) are ported instead, as a small, explainable Python classifier.

**Design (to build).**

1. **Extension** (new `src/erase.{h,cpp}` + pure `src/erase_req.h` with host tests).
   - At each user `strokeCompleted`, send
     `{"t":"pen_stroke","page","sid","tool","n","bbox"(page units),"view":[zoom,dx,dy],"layer"}`
     and keep the last 8 user strokes (points, layer name, time).
   - `{"op":"erase","id","page","layer":"agent","strokes":[{"pts":[[x,y],…]}]}` becomes an `InkJob`
     with `erase=true`, run through ink.cpp's commit chain (the same window and guards; erase jobs
     are never merged with draw jobs; the agent layer is never created for an erase).
     `drawNow` calls `eraseWithLine` instead of `addDrawingLine`, then marks the region dirty.
   - `{"op":"erase","layer":"user","sid","n","bbox"}` erases only one of the user's last 4 strokes,
     younger than 30 s, matched by its fingerprint, and only on the current layer by its recorded
     name. It uses the extension's own points, needs no layer switch, and waits for pen-up.
   - toolfollow needs a listener that also passes the `Line`.
2. **Bridges, Go and Rust.**
   - Extension `pen_stroke` lines go to the router (as `dock_action` lines do, with the doc and ts
     added).
   - Router `ink_erase` (agent: normalized paths converted with `convert()`, so the points are
     identical to the commit; user: sid + fingerprint) becomes the socket `erase` op. It is handled
     on the goto/agent_status path, so it works with agent ink off.
   - Both routers relay `pen_stroke` and `ink_erase` (dispatch.go, client.rs), without recording
     them.
3. **agentd.**
   - New `answers.py`: each answer's strokes in page units, with their line and word. This needs
     `word` + `words` from `packages/hand/scripts/layouts.ts` (additive). The answers are persisted
     per page.
   - New `gestures.py`: the pure classifier.
   - New glue module: a dwell timer and the actions.
   - Small hooks: `service.handle`, `stream.py` (register each chunk), `page.py` (the view from
     `pen_stroke`), `threads.py` (`Exchange.mark`), and `prompt.py` (a follow-up instruction).
4. **Recognition rules (mm).**
   - **Grouping.** A gesture is a burst of user strokes, each starting within 600 ms of the last
     one's lift, with ≥ 600 ms of quiet after it (≥ 1.5 s of quiet before a "?"). A burst of
     1 stroke can be a strike, a circle or a tick; a burst of 2 strokes (hook + dot) can be a "?".
     Anything else is writing. Only `pen_stroke.tool == pen` counts.
   - **Strike.** Straightness ≥ 0.85 and |angle| ≤ 20°. It covers ≥ 60 % of the width of one
     answer line, and its median y lies within that line's 20th–80th percentile y band (so an
     underline does not count). It crosses ≥ 3 of the answer's strokes. A block-level variant
     allows |angle| ≤ 35°.
   - **Circle.** As delegate's loop: |turn| > 1.5π, L > 1.9 D, chord < 0.45 D. It must enclose
     ≥ 2 answer strokes (80 % of their points) and no user ink.
   - **Tick.** One vertex, a short leg down, then a leg up and to the right, the second leg
     ≥ 1.4× the first (so a "v" does not count). It must overlap the answer's block grown by 2 mm.
   - **"?".** A clockwise hook whose start is in the top 40 % and whose end is in the bottom 35 %,
     with a dot below it. It must touch no ink, sit ≥ 6.7 mm from the nearest ink on its row, and
     overlap the rows of a user-ink cluster (single-linkage clusters).
   - **For all.** The answer must still be present in the latest snapshot. A confidence threshold
     applies. Every decision is logged with its features to `gestures.jsonl`; accepted ones also go
     to `requests.jsonl`.
5. **Actions.**
   - **Strike.** Send `ink_erase` for the answer (in chunks of ≤ 32 strokes) and `stroke_delete` for
     the viewers. Then erase the user's strike, but only if no other user ink lies within 2.7 mm of
     its path; otherwise the strike is left and logged. The answer is marked dismissed in its
     thread.
   - **Circle.** An internal `ask_followup`: the circled words (from `word` indices) and the whole
     answer go in as context, and the reply is anchored below the answer. The circle **stays**: it
     is the user's own markup, it shows what the follow-up refers to, and removing user ink is the
     riskiest operation.
   - **"?".** A synthesized `ask_selection` with the cluster's bbox. The "?" stays, for the same
     reasons.
   - **Tick.** `Exchange.mark = "useful"` and a log line; no ink.

**To resume.** Build in this order:

1. `gestures.py` with its tests (synthetic strokes, plus near misses: handwriting across an

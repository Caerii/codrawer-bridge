# Checkpoint, 2026-10-07: Ask on paper

This checkpoint records what is running and verified on the hardware after two days of work on
native agent ink. It also covers how to bring the stack up and what is still open. The design
direction that follows from it is in `docs/design/ask-experience.md`.

dev at this checkpoint: `fd891d9` and the commits of this checkpoint. Tablet release:
`2026.10.07-065136-fd891d9-ce21` (Paper Pro, OS 3.29.0.149, XOVI on, engine rust).

## What a user can do now (verified on the device)

1. **Ask about a lasso or a page.** There are two ways to ask:
   - lasso some ink, then tap the "c" button the extension adds to xochitl's own selection menu,
     after delete;
   - use the "c" dock under redo in the left toolbar: *Ask about this page* or
     *Ask about selection*.
2. **See it think at once.** A doodle appears at the tap, 36 page units (about 4 mm) under the
   selected ink. It is drawn by the tablet without waiting for the network, it stays on the
   paper while the page scrolls or zooms, and it is never saved. When the answer starts, the
   doodle's nib hands off into it.
3. **Read the answer in ink.** About 3–4 s after the tap, the answer starts writing itself in
   under the selection:
   - in a biomechanical hand (`packages/hand`, the Archivist), at about 7 letters/s ("fast");
   - as native reMarkable strokes on the "codrawer: agent" layer, which one undo removes;
   - at a comfortable width, with compact spacing, never over existing ink, and kept on the
     page.
4. **Keep writing meanwhile.** The user's pen is never blocked: the overlay takes no input and
   covers only what it draws. Native commits switch layers in a window of 16–50 ms (mean 19 ms
   over 107 commits), with no strokes misfiled so far. A commit made *while the user's pen is
   down* has not been observed yet, so that case is still open.
5. **Follow a thread.** Asks on the same page carry the page's earlier exchanges as text (memory,
   on by default; local only; per page).
6. **Tune it from the dock.** agentd publishes these rows into the tablet's dock: Memory, Forget
   this page's thread, Model (careful = Sonnet 5.5 / fast = Haiku 4.5), Text size (micro … large),
   Spacing (compact / normal / airy) and Writing speed (calm / fast / very fast).

## How it is wired

```
tablet: xochitl + XOVI codrawer-layer.so ── ink.sock ── bridge (rust) ── router :8577 (session1)
                                                                             │  Wi-Fi / tailnet
PC:                                              codrawer-agentd ───────────┘
                                                   └─ pool of warm `claude -p` processes (stream-json,
                                                      image attached, no tools, empty cwd outside the repo)
```

- **Extension** (`bridge/remarkable/xovi/codrawer-layer/`, literate modules):
  - the ink commit chain;
  - the live overlay (`qml/live.qml`);
  - the dock, the selection "Ask" button, automation, goto, and the probes.
- **Bridge and routers** (`bridge/remarkable/native`, `bridge/remarkable/rust`):
  - relay `dock_action`, `agent_status`, `settings`, `dock_entries` and `goto`;
  - govern agent ink: 30 strokes/s with a burst of 60; y up to 40000 page units.
- **agentd** (`src/codrawer_bridge/agentd/`):
  - placement, rendering and the page model;
  - the warm process pool (`claude_stream.py`) and page threads (`threads.py`);
  - streaming sentence by sentence into the warm hand worker.

### Run agentd

```bash
uv run python -m codrawer_bridge.agentd --ws ws://<tablet-ip>:8577/ws/session1 --token <ROUTER_TOKEN> \
  --ssh root@<tablet-ip> --backend claude-stream --agent-cwd ~/.codrawer-agentd/live \
  --thinking overlay --max-page-y 18
```

It uses the Claude Code subscription login; no API key is needed. Logs and request records go
to `.codrawer/agentd/` (gitignored); settings and page threads stay local.

## Incidents and the rules they left

- **The user's pen was blocked** (2026-10-07 00:00). The first live overlay was a full-page
  Canvas above the page, and xochitl does not let the pen write under another item. Fixed in
  `fe43cd1`. Rule: after every XOVI reload, the first check is that the user's pen writes,
  together with `scripts/dev/pentest.py`. Nothing of ours may take input or cover more than
  it draws.
- **Answers were lost on scrolled pages.** The bridges refused y above 1.5 page heights; fixed in
  `b1331c4`.
- **A late answer reached the wrong ask.** An interrupted Claude turn's result was read by the
  next turn. Now every ask gets its own process, so a tainted session is never reused.
- **A bloated session.** Every image stayed in one long session (turns took 30–70 s). Now each ask
  runs in a fresh, pre-warmed process.

## Open

- **A commit while the user's pen is down:** collect `ink: window … pen down` lines during a long
  answer while the user keeps writing.
- **The doodle's placement** (see the design doc): the tablet proposes the spot and agentd
  confirms it; a move becomes one arc, never two jumps. The extension also has to read the real
  selected-ink bounds; today it reads `textSelectionBounds`, which is 0×0 for ink.
- **A live stroke may block the pen at its own spot while it plays.** Check whether the
  Animation region is the cause.
- **agentd runs in a terminal, not as a service.** It also needs a health row in the dock and a
  nightly on-device regression.
- **The screen grab's colours are still shifted** (open since Probe 1).
